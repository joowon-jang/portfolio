# 장주원 — 웹 개발자 포트폴리오

고객사 AX PoC와 Next.js 풀스택 개발 경력, 개인 프로젝트를 소개하는 빌드 없는 정적 사이트입니다. 승인한 Wave 구성과 LINE Seed KR을 실제 메인에 적용합니다.

운영 주소: https://joowon-jang.github.io/portfolio/

## 실행

```bash
python3 -m http.server 8080
```

`http://localhost:8080/`에서 확인합니다. 별도 설치·빌드 과정은 없습니다.

## 구조

- `index.html` — 한국어 정적 홈, 메타데이터와 공통 자산 로더
- `js/data.js` — ko/en/ja 콘텐츠, 기술 목록, 이미지·영상·링크 메타데이터
- `js/app.js` — 공통 홈·메뉴·언어 전환·해시 라우터·인쇄 상태 관리
- `js/project-detail.js` — 네 프로젝트의 전체 상세 콘텐츠 렌더러
- `js/scroll-motion.js` — AX 데이터 흐름과 실제 AioLM 화면 전환
- `css/style.css` — 승인된 홈 배치·반응형·전체 페이지 배경·인쇄 규칙
- `css/project-detail.css` — 프로젝트 상세·모바일 정보 표·실제 미디어·인쇄 규칙
- `scripts/sync-home.mjs` — 데이터·렌더러에서 한국어 정적 본문과 공통 자산 캐시 버전을 갱신하는 선택적 작성 도구
- `css/line-seed.css` — 버전을 고정한 LINE Seed KR 웹폰트 선언
- `css/theme-wave.css` — 운영 기본 팔레트
- `css/theme-pulse.css`, `css/theme-focus.css` — 보존한 색상 비교안
- `assets/` — 실제 프로필·프로젝트 화면과 얇은 배경 질감
- `mockups/` — 보존한 디자인 검토 기록

자산과 상세 링크는 앱 스크립트의 위치를 기준으로 해결하므로 GitHub Pages의 `/portfolio/` 하위 경로에서도 동작합니다.

## 콘텐츠와 배치

소개 → 연락처·링크 → 기술 → 경력 → 자격증·어학 → 블로그 → 프로젝트 순서입니다. 프로젝트가 마지막 콘텐츠 섹션입니다.

고객사 AX PoC는 경력 최상단의 대표 기여입니다. 도식은 Jira에서 PostgreSQL로 옮긴 데이터와 PDF 등 문서 → 벡터화 → RAG, 검색 맥락의 로컬 LLM 연결, 자연어 질문 → 로컬 LLM → SQL → 조회 결과를 설명합니다. PDF 등 문서가 PostgreSQL을 거치는 것으로 표현하지 않습니다. PoC를 실제 서비스 출시나 단독 개발로 표현하지 않습니다.

경력은 화면 크기에 관계없이 한 열로 나열합니다. 상세는 기본으로 접고, 성과가 있는 항목은 접힌 상태에서도 성과를 표시합니다. AX 이외의 기여는 큰 제목·날짜·성과 배지로 구분하며, SafetyOne은 별도의 밝은 영역으로 묶습니다. 펼치기 행은 좌우 여백을 포함한 전체 너비가 hover·클릭 대상입니다. 날짜가 있는 항목은 최신순입니다.

보유 기술은 `SKILLS.main` / `SKILLS.sub` 두 목록입니다. 주력은 AI 활용·TypeScript·React·Next.js이며 AI 활용을 첫 항목으로 강조합니다. 추가 기술은 Node.js·PostgreSQL·Nginx·WASM·RAG입니다. AI 활용 명칭은 `UI_COPY.aiUsage`에서 번역합니다. 기술 목록에서 제외한 라이브러리도 실제 경력·프로젝트의 사용 기록에는 유지합니다.

AioLM 기간은 확인 가능한 개발 기록을 기준으로 `2026.08 ~ 진행 중`입니다. 앱 초기 기록은 2026년 8월, 웹 초기 기록은 9월이며 기존의 지속 개선 상태를 유지했습니다.

AioLM 소개는 [앱 v0.3.5 소스](https://github.com/aiolm/AioLM/tree/6cc99ca4efbd77a589816c96b94757bb89d844b0)와 [검색 중심 UI로 바뀐 웹 소스](https://github.com/aiolm/AioLm-Web/tree/a032162096fc8a458565bd2dcdcddc0a81010c77)를 확인해 갱신했습니다. 웹의 기본 검색, 필요할 때 여는 상세 조건, 핵심 지표 중심 결과 목록과 비교 흐름을 반영합니다. 추론 엔진 자체를 개발했다고 소개하지 않으며, 공통 API 벤치마크는 클라이언트에서 관측한 응답 시간·출력 바이트 기준으로 설명합니다.

공개 AioLM 소개는 모델 실행·문서 기반 채팅·공통 API 측정·웹 결과 비교 네 가지 핵심 기능에 집중합니다. 검증된 결과·검증 상태 표시·문제 요약·문제 해결·중복 기여 섹션은 제공하지 않으며, CLI·MCP·Skills·소유자 관리 등 부수 기능은 노출하지 않습니다. 대신 개발 배경, 기획부터 앱·웹까지 직접 맡은 범위, 사용 흐름을 구체적으로 설명합니다. 채용용 문구에도 성과 수치·사용자 효과·독립 검증 주장을 만들지 않습니다.

AioLM 대표·상세 이미지는 공개 웹을 실제 브라우저에서 촬영한 1440×1000 PNG입니다. `web-overview.png`는 `/ko` 제품 소개, `web-benchmark.png`는 `/ko/benchmarks`의 상세 조건을 접은 검색·결과 화면입니다. 벤치마크 이미지는 Apple M2에서 실제 Qwen2.5 모델을 AioLM으로 측정하고 정식 공유한 [결과 1건](https://aiolm.vercel.app/ko/benchmarks/bhgaasq6q8r3)이 표시된 화면이며, 기본 6개 측정 조건을 완료했습니다. 예시 결과나 성과 데이터를 합성하지 않습니다. 메인은 제품 소개 → 벤치마크 결과로 전환하고, 상세에는 두 화면만 표시합니다. 상세 조건을 펼친 이미지와 중복 캡처는 사용하지 않습니다. 첫 이미지의 실제 비율을 사용하며, 예전 벤치마크·모델 설정 이미지는 보존 시안에서 사용하므로 유지합니다.

## 탐색과 언어

`#p4`(AioLM), `#p1`(페이스리뷰), `#p2`(토도동), `#p3`(해마디)는 직접 진입 가능한 상세 경로입니다. 목록 복귀, 이전·다음 프로젝트, 브라우저 뒤로·앞으로를 지원합니다. 탐색 기록별 스크롤 위치는 이동·문서 이탈 시점에 저장하고 목적지 DOM을 만든 뒤 복원하며, 스크롤마다 기록하지 않습니다. 새로고침에는 읽기 위치의 세션 스냅샷을 사용하고 복원 후 제거합니다. 저장소 접근이 제한돼도 탐색은 동작합니다. 상세의 ‘맨 위로’는 해당 상세 안에서 이동합니다. `#sec-*`는 홈의 해당 영역으로 돌아갑니다. 같은 홈에서 섹션만 이동할 때 펼침 상태를 초기화하지 않습니다.

한국어·영어 기본 서체는 LINE Seed KR, 일본어는 Noto Sans JP입니다. 일본어 스타일시트는 일본어를 선택하거나 저장된 일본어 설정을 복원할 때 한 번만 요청합니다. 상세에서도 같은 언어·공통 메뉴·팔레트를 사용합니다. 모바일에서 언어를 바꿀 때 열린 메뉴와 선택 버튼의 포커스를 유지하고, 데스크톱 배치로 전환되면 모바일 메뉴 상태를 닫습니다.

## 배경과 모션

그라데이션과 질감은 섹션이 아닌 `body::before`의 전체 화면 고정 레이어입니다. 읽기 영역은 별도 그라데이션 없이 대비를 유지합니다. 배경은 클릭을 가로채지 않으며 자동 애니메이션이나 외부 사진을 사용하지 않습니다.

| 대상 | 시작 위치 — 뷰포트 상단 기준 | 완료 위치 |
| --- | --- | --- |
| AX 도식 상단 | 75% | 15% |
| AioLM 화면의 자연스러운 문서상 상단 | 65% | 15% |

AX는 진행 중인 경로·이동 점·두 노드와 단계별 진행 막대를 강조합니다. AioLM은 앞 화면이 뒤로 기울고 다음 실제 화면이 왼쪽부터 드러나는 전환입니다. sticky 구간에서도 전환이 완료됩니다. 진행률과 정적 모드가 같으면 DOM 갱신을 생략하고, 도식 크기가 바뀌면 경로를 다시 계산합니다. 화면의 레이어 승격은 전환 중에만 적용합니다. 모션 축소 설정에서는 완성된 흐름과 두 화면을 정적으로 표시합니다.

## 인쇄

브라우저에서 홈과 각 상세를 PDF로 저장하거나 인쇄할 수 있습니다. 접힌 기여를 모두 펼치고, 인쇄 후 원래 상태를 복원합니다. 도식은 인쇄 매체가 활성화된 시점에 용지 배치로 다시 측정해 화면용 좌표를 사용하지 않습니다. 영상은 실제 poster 이미지로 출력하며 화면 전환 마스크·전체 배경 장식은 해제합니다. 중요한 이미지는 미리 로딩합니다. 배경색을 포함하려면 브라우저 인쇄 설정에서 **배경 그래픽**을 켭니다.

한국어 홈은 JavaScript를 끈 상태에서도 읽을 수 있는 정적 본문을 포함합니다. 본문을 직접 복사하지 않고, 콘텐츠·렌더러·공통 스타일 변경 후 저장소 루트에서 다음 명령을 실행합니다. 작성 도구만 Node.js 18 이상을 사용하며, 방문자와 배포에는 Node.js나 빌드 과정이 필요하지 않습니다.

```bash
node scripts/sync-home.mjs
node scripts/sync-home.mjs --check
```

`Portfolio.homeMarkup('ko')`에서 운영 페이지와 아홉 정식 비교안의 본문을 생성합니다. 섹션 링크는 같은 문서를 가리키며, 메인의 자산·상세 링크는 `assets/`·`index.html`, 비교안은 `../assets/`·`../index.html` 기준입니다. 페이지별 메타데이터·팔레트·서체 설정과 보존 원본은 유지합니다. 공통 JavaScript 네 파일과 CSS 두 파일의 내용 기반 캐시 버전도 함께 갱신합니다.

`--check`는 파일을 쓰지 않습니다. 최신이면 종료 코드 0, 갱신이 필요하면 1, 잘못된 인자·정적 루트 경계·공통 자산의 중복이나 누락은 2입니다. 모든 대상의 경계와 자산 참조를 확인한 후에만 파일을 갱신하며, 정적 루트는 본문 마지막 요소로 유지합니다.

## 보존한 비교안

`/mockups/feedback-round.html`은 현재 색상안, `/mockups/font-round.html`은 이전 서체 비교입니다. 아홉 개의 정식 비교안은 운영과 동일한 스크립트·스타일을 로드합니다. `flow.html`과 관련 3개 파일, `typeflow.html`, `aperture.html`은 원본 그대로 보존합니다. 이전 라운드는 `/mockups/directions.html`에 있습니다.

## 배포

GitHub Pages는 `main` 브랜치의 저장소 루트를 배포합니다. `.nojekyll`을 유지하며 승인된 변경을 커밋·푸시하면 Pages 빌드가 실행됩니다. 배포 후 운영 루트·프로젝트 직접 링크·자산 경로를 확인합니다.
